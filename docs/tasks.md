# 持久化任务

启用 AI 后，应用自动在配置文件同目录创建 `tasks.db`（权限 `0600`）。`!ai <内容>`、模型快捷命令、已启用的私聊自动回复、群聊提及和回复机器人都会创建任务。数据库写入成功后回复「已接收，任务 #42」，模型调用和工具执行在后台继续；数据库写入失败时不执行任务。

```text
!task run 检查这个项目并总结问题
!task list
!task status 42
!task cancel 42
```

`list` 展示本群最近 20 条任务。`status` 展示发起人、目录、状态、原消息链接、话题、执行记录数量、结果与投递状态。查询限定在当前平台、机器人账号和群内；只有任务发起人可取消自己的任务。取消已结束任务只返回现有结果。

向机器人发送「查看任务列表」「查询任务 42 的状态」「取消任务 #42」会直接调用同一套查询与取消逻辑，不等待模型。其他自然表达可由模型调用 `saber_task` 工具；群和用户身份来自消息入口，模型参数不能覆盖身份。需要及时取消运行中任务时，使用 `!task cancel` 或上述直接识别的中文格式。

任务输入只包含当前任务的系统提示、用户输入及入口解析的引用/图片，不混入其他人的房间历史。后续任务需要的背景请写在新消息中或显式引用相关消息。`!ai clear/context` 仍操作同步会话历史，对持久化任务无影响。

## 执行与恢复

- `tasks` 保存编号、账号、发起人、群、来源消息/话题、工作目录、请求快照、状态、完整运行结果与投递进度；`task_events` 按顺序保存模型尝试、工具开始/结束等执行记录。模型文本增量不逐条写入数据库，完整模型响应仍会保存。
- 同一个账号、群和 Matrix 事件 ID 有唯一约束。重复送达及重启后重送都返回原任务编号；回执使用固定 Matrix 事务 ID。
- 当前聊天入口的工作目录固定为机器人启动目录，与 stdio 工具继承的目录一致，不提供任意切换目录的聊天参数。重启时应使用相同启动目录；发现旧排队任务的目录不同，会记录失败并停止执行，避免操作错误目录。
- 调度器将路径转为绝对路径并解析符号链接。工具暂未声明读写属性，因此同目录的所有任务都串行执行；核心支持不同目录最多 4 个并发任务。运行中的取消请求在执行器退出后才释放目录。
- 启动时 `queued` 任务继续执行，旧 `running` 任务变为 `interrupted`。中断任务不自动重放；工具的开始事件在派发前落盘，结束事件用于辅助核查，但无法证明远端副作用恰好完成了一次。核查后需要继续的工作应明确创建新任务。
- 工具开始日志写入失败时取消运行，防止产生未记录的副作用。保存终态失败时任务保持 `running` 并占住目录，需处理存储故障；重启将其标为中断，不会再次执行。
- 结果与终态先落盘，然后独立发送。网络失败按退避时间只重试汇报；使用相同 Matrix 事务 ID 处理已发送但未确认的情况。回复关系始终指向原消息及原话题。
- 排队取消直接变为 `cancelled`；运行取消通知执行器退出，不能撤销已经发生的外部副作用。停止服务时运行任务标为中断，排队任务保留。

任务正文、附件、工具参数及结果可能包含私密信息；数据库与 WAL/SHM 文件均不可提交。一份数据库只供一个机器人进程使用。超长汇报截断为 12,000 字符，完整结果保留在数据库；执行记录可通过 `Manager.Events` 或只读 SQL 查询 `task_events`。

## 验收

```sh
# 消息去重、两个用户上下文隔离、目录互斥、取消、重启、结果重试
go test -tags goolm ./internal/task

# 模拟 Matrix 与模型：快速回执、命令、自然语言、来源关系和固定投递事务
go test -tags goolm ./internal/ai -run 'TestTasks|TestNaturalTask|TestTaskReply'

# 并发竞态与仓库门禁
go test -race -tags goolm ./internal/task ./internal/ai ./internal/matrix
make fmt-check lint test-cover-check build
```

这些测试使用临时 SQLite 和本地 HTTP 服务；真实 homeserver、E2EE 与模型上游的运行验收需在部署环境完成。
