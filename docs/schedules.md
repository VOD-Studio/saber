# 持久化定时计划

计划与普通任务共用配置目录中的 `tasks.db`，随机器人启动，无需有人在线。单个数据库只能由一个 Saber 进程使用。到点后创建普通任务，复用工作目录串行队列、容器/工具权限、日志、文件交付和结果重试。

## 群命令

```text
!schedule once 2026-10-01T09:00:00+08:00 Asia/Shanghai 检查服务状态并汇报
!schedule every 1h Asia/Shanghai 检查服务状态并汇报
!schedule weekdays 09:00 Asia/Shanghai 检查服务状态并汇报
!schedule cron "*/15 9-18 * * 1-5" Asia/Shanghai 检查服务状态并汇报
!schedule every 1h Asia/Shanghai model=openai.gpt-4o-mini 检查服务状态并汇报
!schedule every 1h Asia/Shanghai 提醒我喝水 --silent
!schedule weekdays 10:00 Asia/Shanghai 用 saber_tweet 先 get 推文 tweet-9，再用 post 发布今日文章推荐 --silent
!schedule edit 12 every 2h Asia/Shanghai model=openai.gpt-4o-mini 检查服务状态并汇报
!schedule edit 12 cron "0 9 * * 1-5" UTC 每日早报 --silent
!schedule run 12
!schedule resume 12
!schedule list
!schedule status 12
!schedule pause 12
!schedule delete 12
```

时间、时区、目标均必填。一次性时间必须是未来的 RFC3339 时间（带 UTC 偏移）；周期使用 Go duration，例如 `30m`、`2h`、`24h`，范围 1 分钟到 365 天，不支持 `1d`。工作日指周一至周五，不含法定节假日调整。时区使用 IANA 名称，不能使用 `Local`。目标末尾的 `--silent` 表示静默投递（见下文「投递方式」）。目标前可加 `model=<provider.model>` 选项为单条计划指定模型。

### cron 表达式

`cron` 规则使用标准 5 段表达式 `分 时 日 月 周`，因为含空格，命令里必须用单引号或双引号整段包裹：

- `分` 0-59、`时` 0-23、`日` 1-31、`月` 1-12、`周` 0-7，其中 `0` 和 `7` 都表示周日。
- 支持 `*`、单个数字 `n`、范围 `a-b`、步长 `*/n` 和 `a-b/n`，以及逗号列表，例如 `1,15,45 9-18 * * 1-5`。
- 不支持秒级或 6 段表达式、`L`/`W`/`#` 等扩展语法、月份/星期英文名；任何非数字、反向范围或零步长都会报错。
- 日和周同时受限时按标准 cron 语义处理：两者任一匹配即触发；其中一个为 `*` 时只由另一个约束。
- 下一次时间始终在计划保存的 IANA 时区内按墙钟计算，与进程本地时区无关；月末（如只在 31 日）、跨年、闰年和夏令时都按该时区日历推进。夏令时不存在的墙钟时刻跳过，重复的墙钟时刻只执行一次。

例如 `cron "0 9 * * 1-5"` 表示每周一至周五本地时间 09:00；`cron "0 0 31 * *"` 只在有 31 日的月份触发。

回执包含计划编号、规则、时区、负责人、目标、投递方式、执行模式和带偏移的下次执行时间。例如：

```text
计划 #12：每个工作日 09:00，Asia/Shanghai（active）
负责人：@alice:example.org
目标：检查服务状态并汇报
模型：openai.gpt-4o-mini
汇报到：!room:example.org
投递：回复原消息
执行：需要执行授权
下次执行：2026-09-22T09:00:00+08:00
```

创建时按当前授权计算该身份可用的工具集合，并把「是否需要执行授权」冻结到计划上：

- 集合中包含本地执行工具（`exec`、`read_file`、`write_file` 等）或 MCP 工具时，计划需要执行授权：创建人必须已由管理员在 `execution.grants` 授权当前账号、群、用户和工作区，配置见 [执行权限](execution.md)。这类计划每次到点和从队列进入执行前都按当前授权复查，授权撤销或工作目录改变时自动暂停。
- 集合中只有内置聊天工具（任务、计划、记忆、历史、技能查询）时，计划是纯聊天计划，不要求执行授权，工作目录固定为机器人启动目录，与普通无工具聊天任务一致。创建、到点和排队执行都不检查 `execution.grants`；运行时按计划标记再次裁剪工具集合，只保留内置聊天工具，即使创建后用户获得了执行授权，纯聊天计划也不会拿到执行或 MCP 能力。

负责人、工作目录和汇报群从可信消息和服务端配置取值，不提供跨群、代他人或任意目录参数。授权配置为启动时快照，修改配置后重启生效。

## 每个计划的模型与时区

- 创建时可用 `model=<provider.model>`（工具字段 `model`）为单条计划指定模型，例如 `model=openai.gpt-4o-mini`；未指定时使用当前全局默认模型。模型必须已在 `ai.providers` 中配置，未知模型在创建前直接报错，不落库。
- 模型冻结在计划的请求快照里，之后切换全局默认或重启都不会改变已有计划；要换模型请用 `!schedule edit`。
- 时区随 `spec.timezone` 保存。每次计算下一次时间都用该 IANA 时区按墙钟推进，不依赖进程本地时区，因此同一 cron 规则在不同时区的计划会得到不同的绝对时间。

## 编辑、立即执行与恢复

- `!schedule edit <ID> <once|every|weekdays|cron> <时间或周期> <时区> [model=模型] <目标>`：按与创建相同的规则重新计算，可选 `--silent` 修改投递方式；保留原消息、负责人和房间，更新规则与请求快照，把计划恢复为 `active` 并重算下次时间。一次性计划的新时间必须在未来。省略 `model=` 时沿用计划原模型。
- `!schedule run <ID>`：立即生成一次普通任务，但不改变计划的下次时间，也不推进规则；同一计划同一毫秒的重复调用返回同一条决策记录，不会重复建任务。上次任务仍为 `queued`/`running` 时返回 `skipped` 并记录原因。
- `!schedule resume <ID>`：把 `paused` 计划恢复为 `active` 并按当前规则重算下次时间；一次性计划时间已过时需先用 `edit` 修改。`deleted` 计划不可恢复，已删除计划也不能编辑或立即执行。
- 三者权限与暂停一致：负责人或 `execution.task_admins` 授权的本群管理员。`run` 仍按计划的 `requires_execution` 语义执行：纯聊天计划免授权，带执行能力的计划在创建任务前按当前授权复查，撤销时把计划置为 `paused` 且不建任务。

已授权用户也可直接交办“每个工作日 09:00，Asia/Shanghai，检查服务状态并汇报到本群”。模型通过 `saber_schedule` 调用与命令完全相同的逻辑，参数不能指定身份、目的群或目录；`delivery` 可选 `origin`（默认）或 `silent`。纯聊天计划不要求执行授权，没有授权的成员也可以直接说“每天早上九点提醒我喝水，不用发到群里”。没有明确时间或时区时应先补充；确定性命令不依赖模型。每条原消息最多建立一个计划，重复事件或重复工具调用返回原计划，不能复活已删除计划。

## 定时发布推文（Violet）

自主发帖不需要新调度器：把它当作一次普通定时任务，让模型在运行中调用 `saber_tweet`。计划创建时按当前授权冻结工具集合，`saber_tweet` 属于内置聊天工具，因此不需要 `execution.grants` 的工作区授权，也能被纯聊天计划冻结并在运行时保留。

```text
!schedule weekdays 10:00 Asia/Shanghai 推荐今天的新文章并发布一条推文 --silent
```

管理员的计划可以要求模型先读后写，例如：

```json
{"action":"get","tweet_id":"tweet-9"}
{"action":"post","content":"今天的文章：……","quote_of":"tweet-9","images":["assets/cover.png"]}
```

- `--silent`（工具字段 `"delivery":"silent"`）让计划不向聊天发送回执或结果，推文照常发布，执行记录仍可用 `!task status <ID>` / `!task logs <ID>` 查询。
- 写操作在执行时按 `commands.admins` 重新授权，创建计划时的授权不能替代当前配置；撤销管理员后旧计划会在工具调用处失败，而不是继续公开发布。
- 每日上限 `platforms.violet.tweets.max_posts_per_day` 与最小间隔 `min_post_interval_minutes` 由进程内状态执行，重启清零；达到上限时工具返回明确错误并提示等待，不会静默跳过。
- 相同任务内相同参数的重试复用同一幂等键，不会重复发帖；不同任务或不同参数各自独立。
- 定时任务同样能用 `saber_emoji`：它属于内置聊天工具，纯聊天计划可以冻结并携带；到点后模型可先 `list` 查 token、对见过的自定义表情 `favorite`，再把 token 原样写进推文或评论正文，不需要额外的调度或配置。

## 投递方式

- `origin`（默认）：结果回复创建计划的原消息/话题；各次发生有独立投递幂等键，发送失败只重试汇报和文件投递，不重新执行。
- `silent`：不向聊天发送正文，也不发送文件产物；结果仍完整写入任务库，可用 `!task status <ID>` / `!task logs <ID>` 查询。静默任务的投递状态直接记为 `sent`，不会因为“没发出去”进入重试队列。

命令在目标末尾加 `--silent`，工具使用 `"delivery":"silent"`；两者同时出现时以静默为准。未知投递目标在创建时直接报错，不会落库。当前只支持 `origin` 与 `silent`，不提供显式跨群投递；需要把结果发到别处时，让计划把内容写进结果并用 `origin` 或静默落库后人工转发。

## 定时运行的记忆与技能

定时任务不在原始聊天轮次里运行，运行时从计划保存的原消息快照重建作用域后再决定注入什么：

- 快照是创建者本人的私聊（`Direct` 且发送者与当前可信身份一致）时，注入创建者个人记忆。
- 快照是群消息时，只注入该群作用域的群记忆，私聊记忆不会进入群任务。
- 技能目录与记忆使用同一份重建后的可信身份查询。
- 快照中的会话、发送者或私聊标记与当前可信身份不一致，或记忆服务未启用时跳过注入；绝不跨用户、跨群猜测作用域。

注入只发生在本次运行的请求上，不写回计划保存的请求快照。

## 执行与恢复规则

- 计划保存独立目标和模型请求快照，不携带创建时的群聊历史或工具结果；每次执行按当前授权重新筛选工具，纯聊天计划再裁剪为仅内置聊天工具。
- 触发记录、普通任务入队和下次时间在同一 SQLite 事务提交；重启不重复发生。
- 离线错过的周期合并为至多一次执行，然后直接推进到未来；不逐次补跑。固定周期保留原始相位。一次性错过时间会在恢复后执行一次。状态记录同时保留应执行时间、实际处理时间和合并说明。
- 上次普通任务仍为 `queued` 或 `running` 时跳过本次，记录 `skipped`，不再补跑。已完成但汇报失败不算仍在执行，其汇报独立重试。
- 重启时运行中的普通任务标记 `interrupted`，不重放；排队任务继续。计划未来的发生是新的任务，不等于重放上次执行。
- 暂停/删除阻止后续触发和尚未进入执行的排队任务，不强杀已经运行的任务；终止运行请用 `!task cancel <ID>`。暂停后可用 `!schedule resume <ID>` 恢复并按当前规则重算下次时间，或用 `!schedule edit` 改规则；已删除计划不可恢复。
- 删除为软删除，保留触发审计和事件去重。`list` 不显示已删除计划，`status` 仍可按编号查询。负责人或 `execution.task_admins` 授权的本群管理员可编辑、立即执行、恢复、暂停和删除计划；状态查询限定在所属账号和群。
- `!schedule run` 与自动触发走同一条建任务与决策记录路径，但不推进 `next_run`；同一毫秒的重复调用复用已有决策记录，因此命令重投不会重复执行。
- `origin` 结果回复创建计划的原消息/话题；各次发生有独立投递幂等键，发送失败只重试汇报和文件投递，不重新执行。`silent` 不发消息也不发文件，任务记录直接标记投递成功，结果用 `!task status <ID>` 查询。
- 工作日与 cron 都按计划时区的本地日历计算：夏令时不存在的墙钟时刻跳过，重复墙钟时刻只选一次。二进制内嵌时区库，精简容器不必另装 tzdata。

计划 `status` 显示最近触发决策与普通任务编号。执行记录、取消和投递状态继续使用 `!task status <ID>` / `!task cancel <ID>`。

旧版本的 `tasks.db` 在启动时自动补齐 `tasks.silent`、`schedules.requires_execution`、`schedules.delivery` 三列：旧计划按“需要执行授权、回复原消息”继续运行，旧任务按“非静默”处理，迁移可重复执行。

```bash
make test-cover-check

```

自动化覆盖时间规则、cron 解析与非法表达式、时区与夏令时（不存在/重复墙钟）、月末与周日组合、跨时区下次时间差异、事务回滚、重复创建/触发、离线合并、上次未结束、暂停/删除/编辑/恢复、立即执行的幂等与授权复查、per-job 模型冻结、到点和排队后撤权、纯聊天计划免授权创建与执行、带工具计划仍要求授权、静默投递不发送但终态落库、私聊/群记忆作用域隔离、旧库列迁移，以及实际 SQLite 关闭重开和模拟 Matrix/模型端点下的无人发消息自动执行、原消息/话题关联、结果发送失败仅重试投递。真实 homeserver 与真实模型的在线验收需另行运行。
