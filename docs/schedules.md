# 持久化定时计划

计划与普通任务共用配置目录中的 `tasks.db`，随机器人启动，无需有人在线。单个数据库只能由一个 Saber 进程使用。到点后创建普通任务，复用工作目录串行队列、容器/工具权限、日志、文件交付和结果重试。

## 群命令

```text
!schedule once 2026-10-01T09:00:00+08:00 Asia/Shanghai 检查服务状态并汇报
!schedule every 1h Asia/Shanghai 检查服务状态并汇报
!schedule weekdays 09:00 Asia/Shanghai 检查服务状态并汇报
!schedule list
!schedule status 12
!schedule pause 12
!schedule delete 12
```

时间、时区、目标均必填。一次性时间必须是未来的 RFC3339 时间（带 UTC 偏移）；周期使用 Go duration，例如 `30m`、`2h`、`24h`，范围 1 分钟到 365 天，不支持 `1d`。工作日指周一至周五，不含法定节假日调整。时区使用 IANA 名称，不能使用 `Local`。

回执包含计划编号、规则、时区、负责人、目标、汇报群及带偏移的下次执行时间。例如：

```text
计划 #12：每个工作日 09:00，Asia/Shanghai（active）
负责人：@alice:example.org
目标：检查服务状态并汇报
汇报到：!room:example.org
下次执行：2026-09-22T09:00:00+08:00
```

创建人必须已由管理员在 `execution.grants` 授权当前账号、群、用户和工作区，配置见 [执行权限](execution.md)。负责人、工作目录和汇报群从可信消息和服务端配置取值，不提供跨群、代他人或任意目录参数。计划不会获得额外执行权限。授权配置为启动时快照，修改配置后重启生效；每次到点和从队列进入执行前都按当前授权复查，授权撤销或工作目录改变时自动暂停。

已授权用户也可直接交办“每个工作日 09:00，Asia/Shanghai，检查服务状态并汇报到本群”。模型通过 `saber_schedule` 调用与命令完全相同的逻辑，参数不能指定身份、目的群或目录。没有明确时间或时区时应先补充；确定性命令不依赖模型。每条原消息最多建立一个计划，重复事件或重复工具调用返回原计划，不能复活已删除计划。

## 执行与恢复规则

- 计划保存独立目标和模型请求快照，不携带创建时的群聊历史或工具结果；每次执行重新筛选工具。
- 触发记录、普通任务入队和下次时间在同一 SQLite 事务提交；重启不重复发生。
- 离线错过的周期合并为至多一次执行，然后直接推进到未来；不逐次补跑。固定周期保留原始相位。一次性错过时间会在恢复后执行一次。状态记录同时保留应执行时间、实际处理时间和合并说明。
- 上次普通任务仍为 `queued` 或 `running` 时跳过本次，记录 `skipped`，不再补跑。已完成但汇报失败不算仍在执行，其汇报独立重试。
- 重启时运行中的普通任务标记 `interrupted`，不重放；排队任务继续。计划未来的发生是新的任务，不等于重放上次执行。
- 暂停/删除阻止后续触发和尚未进入执行的排队任务，不强杀已经运行的任务；终止运行请用 `!task cancel <ID>`。第一版不提供恢复/编辑命令，需要时以新消息重新创建。
- 删除为软删除，保留触发审计和事件去重。`list` 不显示已删除计划，`status` 仍可按编号查询。只能修改自己的计划；状态查询限定在所属账号和群。
- 每次结果仍回复创建计划的原消息/话题；各次发生有独立投递幂等键，发送失败只重试汇报和文件投递，不重新执行。
- 工作日按本地日历计算：夏令时不存在的墙钟时刻跳过，重复墙钟时刻只选一次。二进制内嵌时区库，精简容器不必另装 tzdata。

计划 `status` 显示最近触发决策与普通任务编号。执行记录、取消和投递状态继续使用 `!task status <ID>` / `!task cancel <ID>`。

## 验证

```bash
go test -race -tags goolm ./internal/task/... ./internal/ai/...
make test-cover-check
make lint
make build
```

自动化覆盖时间规则、时区与夏令时、事务回滚、重复创建/触发、离线合并、上次未结束、暂停/删除、到点和排队后撤权、实际 SQLite 关闭重开，以及模拟 Matrix/模型端点下的无人发消息自动执行、原消息/话题关联、结果发送失败仅重试投递。真实 homeserver 与真实模型的在线验收需另行运行。
